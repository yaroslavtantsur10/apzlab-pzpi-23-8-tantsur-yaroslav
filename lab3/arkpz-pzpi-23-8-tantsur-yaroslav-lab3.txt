3.1 Мета роботи 
Метою лабораторної роботи є набуття практичних навичок проектування та розробки клієнтської частини (Front-end) багатокористувацької вебсистеми з розподіленим доступом, що передбачає створення окремих функціональних інтерфейсів для звичайних користувачів і адміністраторів відповідно до їхніх ролей. Робота спрямована на опанування методів інтернаціоналізації та локалізації, включаючи впровадження підтримки української та англійської мов та адаптацію форматів дати й часу 
 
3.2 Опис прийнятих інженерних рішень 

Клієнтська частина реалізована на базі бібліотеки React (TypeScript), що забезпечує компонентний підхід до побудови інтерфейсу та реактивне оновлення даних без перезавантаження сторінки.
Для маршрутизації використовується React Router v6, що дозволяє реалізувати захищені маршрути (PrivateRoute) окремо для ролей «Гість готелю» та «Адміністратор».
Для HTTP-запитів до серверного API використовується бібліотека Axios з перехоплювачем (interceptor), який автоматично додає JWT-токен до заголовків запитів.
Інтернаціоналізація реалізована за допомогою бібліотеки i18next, яка забезпечує підтримку двох мов (української та англійської), форматування дат і часу відповідно до регіону, а також різні напрями введення тексту.
Управління глобальним станом застосунку реалізовано через React Context API — зокрема для зберігання інформації про авторизованого користувача та поточної мови інтерфейсу.

3.3 Опис взаємодії компонентів web-застосунку одне з одним та з іншими елементами системи 

Веб-застосунок побудований за багаторівневою архітектурою і взаємодіє з іншими частинами системи через REST API.
Внутрішня взаємодія компонентів React:
* Pages — компоненти верхнього рівня (LoginPage, DashboardPage, AdminPage тощо), які відповідають за відображення окремих сторінок застосунку.
* Components — перевикористовувані UI-елементи (SensorCard, NotificationList, UserTable), які отримують дані через props від Pages.
* Services — модулі для роботи з API (authService, sensorService, adminService). Виконують HTTP-запити через Axios і повертають дані до компонентів.
* Context — AuthContext зберігає стан авторизації (токен, роль користувача) та надає його будь-якому компоненту в дереві.
* Router — React Router розподіляє маршрути між гостем готелю та адміністратором, блокуючи доступ до захищених сторінок без авторизації.
Взаємодія з іншими частинами системи:
* Веб-клієнт надсилає HTTP-запити до ASP.NET Core API та отримує у відповідь JSON-дані.
* Авторизація відбувається через endpoint /api/Auth/login, у відповідь сервер повертає JWT-токен, який зберігається в localStorage і додається до кожного наступного запиту.
* Адміністратор через веб-інтерфейс може переглядати дані з IoT-датчиків (ESP32), які сервер зберігає в базі даних MSSQL.
* Мобільний клієнт (Android) та веб-клієнт працюють з одним і тим самим API незалежно одне від одного.

3.9 Висновки 
У ході виконання лабораторної роботи було розроблено клієнтську веб-частину програмної системи ComfortSpace з використанням бібліотеки React та інструменту збірки Vite. Реалізовано розмежування інтерфейсів для двох ролей користувачів — гостя готелю та адміністратора — відповідно до рольової моделі системи.
Для взаємодії з серверною частиною використано бібліотеку Axios з перехоплювачем запитів, який автоматично додає JWT-токен авторизації до кожного запиту. Захист маршрутів реалізовано через компонент PrivateRoute, який перевіряє наявність токена перед відображенням сторінки.
Адміністративний інтерфейс забезпечує перегляд та управління користувачами системи, а також перегляд даних датчиків з можливістю експорту у форматі JSON та створення резервних копій.
Отримані результати підтверджують працездатність розробленої архітектури та коректність взаємодії веб-клієнта з серверною частиною через REST API.
